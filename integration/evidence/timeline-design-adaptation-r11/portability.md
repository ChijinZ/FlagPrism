## 五部件是否足够，是否过度框架化

五项按变化原因拆分，而不是按厂商强制继承，边界合理：

| 部件 | 能复用的实际内容 | 接新目标仍必须承担的成本 | 判断 |
| --- | --- | --- | --- |
| compiler hook | 相同工具链中合法 pass 接入、通用控制流与 source/site 处理、兼容 logger lowering | 新编译链接入、实际执行主体和地址表达、优化后 M:N 映射、最终对象读钟与边界证明 | 必需；通常是最大适配成本，不能降为配置 |
| launch transport | 相同 runtime 下 context/queue、初始化、提交、完成、readback 的通用路径；公共 owner 状态机和 admission | 新 runtime 的 executable 身份、资源集合、发布/完成语义、guard、异常与恢复 | 必需；运行时相同不自动保证布局或可见性相同 |
| physical decoder | ABI/commit/字段单位真正相同的纯 bytes 转换 | 新布局、padding、字段 offset、坏记录诊断与旧格式兼容 | 必需；和 transport 分开能避免一个格式变化迫使重写 runtime |
| clock provider | 整数/有理数换算算法和已有证据覆盖范围内的 getter 实现 | 型号/getter/位宽、比例与误差、reset/window、epoch 和跨主体关系 | 必需；算法复用不能代替物理证据 |
| mechanism mapper | 相同机制语义下 submit/group/wait 规则与状态机 | 新机制的状态变更闭合、动态身份、批量/部分 wait、多消费者、物理 slot/flag 与 generation | 必需；允许同目标多个 mapper 是合适的 |

公共 manifest、canonical schema、owner、validator 和 exporter 是这些部件共享的交接与消费链，不必再称为第六个可替换后端。设计 §0.1、§8.11–§8.14 明确允许现有函数组合、先有实际调用者再抽取，没有要求五套基类、插件管理器或兼容条件全排列。工作包数量也没有被当作低成本的证据。

设计 §0.4 的“时间与异步解释”合列为一个交付工作包，不改变 clock provider 与 mapper 两项独立取证的事实；§0.4 行 63 已明确“两项独立取证”，不构成把两类资格重新捆绑。

新增目标需要的不是“整条链完全不改”，而是能解释每项复用、补证、替换及公共扩展的原因。这是可实现且诚实的可移植性目标。没有第四设备时，三个真实后端能验证共享边界，不能证明任意第四架构容易接入；设计和测试均正确保留了这个限制。

## 公共 schema、资格与非 CUDA

**M:N 与时间归属分离合理。** 设计 §0.4、§8.1、§8.6、§8.14 要求多 origin、split/fused/eliminated/unknown、真实 actor 与最终 anchors，明确禁止把 fused 的同一 duration 复制成两个阶段凑门槛。源码 `timeline_events.py:113–124` 已允许一个 site 的 `source_ids` 列表，多个 site 也可引用同一 source；这说明基本 M:N 导航没有被一对一字段先天封死。它尚不证明最终边界收据、优化状态和完整执行归属已经实现。

**按结论授予资格优于单个支持开关。** §8.10、§8.14 和测试 §0.1/§8.9 区分 raw 完整性、单位、边界、端点误差、epoch、逻辑关联、物理复用。仅有比例时保隔离 counter-ns，缺边界时只称 counter bracket，缺比较证明时不画时间 flow，与完整交付仍要求真实源区间和异步闭环并不矛盾。源码 `timeline_views.py:1–5,110–141` 已按这个有限范围输出，不能误读为完整源区间能力。

**公共层不需要证明任意机器码。** §8.14 行 509 将公共层限定为身份/范围/引用验证，把支持的通用机器模式检查交给后端，并明确陌生优化形态未证。此划分可执行；它仍要求编译实现维护足够宽的通用模式，不能靠每个算子人工盖章。

**非 CUDA 合同没有强加 CUDA 对象。** 设计 §8.13 明确 loaded executable、context/queue、layout 可由后端类型化封装，不准伪造 function/stream/num_ctas。源码 owner 已将 executable 验证委托给 transport（`timeline_runtime.py:105–110`），GCU/Ascend 使用带 binary 身份的后端 executable 描述（`timeline_enflame.py:69–74`、`timeline_ascend.py:60–69`），并将 `num_ctas=None` 传给自己的布局计算。当前三个实现可沿此边界共享 owner。

当前 owner 仍要求非负整数 stream，并保留 `num_ctas` 形参（`timeline_runtime.py:97–121`）。这对未来使用非整数 queue 对象的 runtime 是需要改动的实现边界，不能声称现有签名已完全通用；但本设计已明确允许在真实调用者出现时抽取合适合同，没有要求未来 transport 伪造值。当前应记录实际支持范围，未来遇真实不兼容对象再扩 typed 输入，不必现在预建抽象层。

## 版本、离线补证与恢复

设计将物理 ABI、canonical schema、decoder revision、proof/rule、派生结果分开版本化是必要的。不同 decoder 可从同 raw 产生不同 canonical revision，不覆盖旧结果，解决了“原件不可变”和“reader 可以升级”的冲突。旧 reader 对未知必需语义拒绝/partial，避免扩展字典绕过验证；必要新语义允许进入公共合同并回归已有后端，避免为零公共 diff 把事实藏回厂商代码。

schema 1/2 当前保守拒绝回绕、未来版本保 modulo tick 并在有独立窗口时唯一展开，也是一条可执行迁移路径。设计和测试明确：若真实必需样本发生回绕，就必须实现并验证新版本，不能以 partial 完成资格。这是实质工作，不是要求设备原始 counter 永不回绕。

§8.14 的输入闭包、实际实现指纹、完成收据、原子索引和有界 OS 锁足以支撑跨进程离线重导与故障恢复。测试 §0.1 行 35 对“离线”证据强度的限制尤其合适：隐藏设备环境变量不能冒充操作系统隔离。fixture 只证明其覆盖的合同，不冒充设备或 UI 通过。

该存储方案比最初 raw decoder 复杂，但原件不可变、升级补证、并发重导与首次结果保留已是明确要求，复杂度有实际需求来源。设计限定只核三后端实际依赖边，不建立通用全排列兼容平台，范围没有失控。

R1–R5 的共同特点是设备/编译产物可能证伪设计候选。现阶段不能宣称 SDK 必然足够，也不能把尚未完成的实现当成硬件不可能。设计 A/B→C→D、失败先保最小输入并停止扩量的策略，正好把这些风险挡在独立全量矩阵之前。

## 验收是否可执行，是否藏有逐算子适配

测试 §0.1 的五项动作有输入、有判定、有真实证据要求，且都映射到已有 P01–P10；没有再增加一套通过状态或第四芯片。公开 API/CLI、原 owner/cache 不可用的新进程重导、逐部件错配、proof 范围隔离、真实 writer 与 guard，比“能注册 adapter”或“有少量代码”更能检查适配结果。

全量数学、故障 fixture、真实 SQL、实际 UI 与最终代码审阅分工合理。设备正例与 CPU fixture、旧 raw 重读、手工探针的证明边界均明确；P03 也不要求设备强行生成从未发生的优化变换。两流/host-thread/graph 按冻结支持表测试，避免把 CUDA 并发能力无条件强加给全部 runtime，同时禁止失败后改分母。

防逐算子适配的约束能够执行：源码名/SSA/site/hash 不用于识别算子，shape 只服务合法布局/预算；独立不同数学先冻结；合法普通输入的 profile 失败保留；未知通用 lowering 不得靠白名单排除。最终对象证据按通用控制/指令模式建立，而非按算子人工书写 pass。要注意的是“模式检查器不断增加通用优化模式”本身是不可消除的编译工程成本；只要规则作用于结构且独立数学回归有效，它不等于逐算子特判。

新增测试 §0.1 所列 multi-function/auto-blockification 范围是对声明范围的约束，没有声称当前实现已经支持全部合法 lowering。实际范围不足仍会是产品缺口，不能用接入清单将失败洗成支持。

总体上，验收严格但可分步执行，不要求一次做完所有矩阵再发现核心机制不可用。当前代码已有部分共享调用证据，后续是否全部可行仍取决于完整 P01；本次评审只能确认任务分配、证据路径和失败处理合理。

## 最终建议

允许继续实施，修正 F1 的阶段措辞即可；不建议再增加适配框架或第四设备来“证明通用”。接下来应继续以三个现有目标的最小真实纵向样本闭合 R1–R5，再扩独立资格。最终报告分别给 raw、本地时间、跨主体/异步、公共 Perfetto 的结果，保留未通过项和真实成本，不压成“支持 timeline”的勾选。
