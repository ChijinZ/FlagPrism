### 时间功能与可选静态归属的界限

本报告判断的是实际 observer 的 issue/wait/原 LLVM block-fragment elapsed 区间。source 链接与融合成员导航不拆分 duration，不承诺某行全部指令的 exclusive cost；原 wait 返回也不等于精确 engine end/busy。reader 精度、全参与、source iteration ID、跨 SIP epoch 等原未证事实继续未知。

R104 的直接原件说明为什么不能以静态 unknown 判 runtime failure：`inventory-receipts-v2/inventory-index-v2.json` 八项本地 size/SHA 全匹配；controller terminal 0；96/96 从实际原件 fresh 重算，无 unavailable。32 是 compiler identity 数、28 是 final binary 数，不能混用分母。去掉静态 status 筛选后，96 份均 capture complete，所有 observer complete/drop=0，每调用有 **4–7 个不同正 source origin**。q01/q02 每调用各有两个重复 origin；q05/q07 等有三个。q01-s0-c0 的 site18/source14 与 site19/source17 因 indexed opaque type 被辅助规则标 unknown，但实际各有两个 observer、各 observer 三个 committed interval。这些区间没有因诊断 unknown 消失，也不能由诊断失败推出 timer 错误。

这不等于仅凭正 duration 证明任意源码成本。肯定依据还包括已核通用 producer 的原 block-fragment 位置与 retained 原 body、实际 source/site/program 载体、tuple/observer 身份、同对象编译交接，以及既有有限 SDK/native family 审计。当前 `AscendLateObserver.cpp` 在原 marker 前及原片段下一个 marker/terminator 前放两端，保留原 block、body 文本/SHA 和 source ID；`timeline_ascend_regions`/R100 的 tuple 规则与 R103 的 fresh raw join 分别提供端点与动态引用。此组合可支持已经声明的 observer 区间，不升级为全体 source 成员/所有 native 路径证明。`native_schedule_qualified=False` 或可选 fragment status unknown 本身不构成新增阻断。

GCU 原 R091 的“必需区域适用索引”现有直接补项：R098 `required-receipts-v5` 108 项 size/SHA 全匹配，33 个对象、96/96 case covered，全部从原 raw fresh decode；冻结 required plan SHA 为 `01d43bf102300630876f4bcfbb2663058c987ce7f6722f2b6012a174012d79b6`。每调用有 body/输出 issue 的预选义务与实际 rule/site/record/raw witness；其中规则结果含 48 个 constant-iteration、24 个 runtime-iteration 连接，其余明确 no enclosing loop。它连接的是有限 typed family 与已审实际 native family，未声称通用 ISA 或完整 native schedule。R094–R098 的编译交接/实际 linked fallback 输入与 binary 绑定及正常安装均有独立受影响闭环。
