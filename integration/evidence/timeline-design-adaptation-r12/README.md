# R12 时间线设计与验收：独立评审及处置

本轮只更新工具设计与验收文档、进行三名 fresh-context subagent 独立评审；未连接服务器或执行产品/设备测试，未修改论文或原有在研产品代码。三名初审不互读报告，均检查整体合理性与实际可行性；模型继承父 agent，未指定模型覆盖。本轮设计评审不替代实现结束后额外三名代码 reviewer。

## 文档入口

- [技术设计 §0.5–§0.6](../../../Profiler/docs/timeline_design.md#05-本轮必须留下的可移植接口以及不提前建设的接口)：公共边界、新算子/新型号/新执行模型的区别、有限通用边界规则及 observer 覆盖；另澄清 §8.7 解码编排、§8.13 deadline。
- [验收 §0.2](../../../Profiler/docs/timeline_testing.md#02-公共边界与新增算子能力的针对性验收)：真实调用、不逐算子批准、共享消费者、语义错误负例、参与范围及阻塞 fixture。

## 三份独立意见与处置

三份初审均为**有条件可行**：职责合理，存在有限、可执行的工程路径，但不能保证三后端待证硬件条件必然满足。初审原文及修订后有限复核均保留在各报告内。

| 报告 | 主要意见 | 文档处置与原 reviewer 复核 |
| --- | --- | --- |
| [编译与边界](compiler.md) | 两项 P1：首批自动边界最低规则和自洽语义反例不足；P2：observer 参与覆盖需明确 | §0.6 定义直线依赖、runtime 循环/路径和原 wait 规则，含 helper/caller、参与条件、版本与失败路径；验收加合法对照及语义负例。设计层均关闭 |
| [运行时与恢复](runtime.md) | SDK/文件系统阻塞时，库 API 软截止与外层控制器保证不清楚 | §8.13 区分软截止/进程截止/设备完成，明确未保存和隔离状态；验收加自有阻塞子进程 fixture。设计层关闭 |
| [可移植性与整体链](portability.md) | 语义负例不足；旧表可能混淆 physical decoder 与 clock provider | 复用边界规则修订，§8.7 明确 decoder 独立、provider/mapper 分别供事实。设计层关闭；真实检查器风险仍待实现消除 |

三人有限复核均无新增设计阻断项。后续最关键的实证风险仍是最终对象中的自动边界及普通流水保持、真实发布/完整资源生命周期、时间尺度/跨主体比较、异步两代物理复用。这些只能靠后续真实实现与验收解决，不能由评审票数消除。没有新增第四设备、独立数学矩阵或插件平台，也没有降低完整交付标准；不承诺新芯片只加配置即可。

[request.json](request.json) 保存初审输入摘要；[final-document-sha256.json](final-document-sha256.json) 保存最终文档摘要；[preserved-product-sha256.json](preserved-product-sha256.json) 用于核原有 dirty 产品/测试内容保持不变。仅完成本地链接目标、摘要和 Git whitespace 检查，不把文档检查当产品测试通过。
