# r12 独立设计评审：运行时、恢复与离线消费

评审范围：只读 `Profiler/docs/timeline_design.md`、`timeline_testing.md` 全文，重点设计 §0.5、测试 §0.2；补读 `Profiler/python/flagtree_profiler/timeline_runtime.py` 与 `hooks/timeline.py` 的实际调用和状态处理。未读其它同轮报告，未连接服务器，未 import 产品、运行产品或测试，未处理 dirty 产品代码。本文件是静态设计意见，不是设备、安装、性能或验收证据。

## 结论：有条件可行

整体职责划分合理，未发现必须推翻方案的架构矛盾。compiler/transport/decoder/clock/mapper 按变化原因分工，公共层保留身份、预算、资格验证和展示，能够容纳三种异构执行模型；§0.5 明确不把现有 CUDA 签名变成跨后端合同，也不要求先造插件框架，实施成本可控。

方案具备可执行的收敛路径：先普通 runtime-K 循环和真实异步最小样本，逐项证伪边界、发布、时钟和机制，再扩独立资格。风险主要来自三后端尚待证明的机器边界、发布语义、时间尺度与动态异步身份。当前文档已正确承认这些风险；本次不能判断它们已经可用，更不能据文档承诺三后端完整目标必然实现。

运行时部分特别合理的是：初始化也视为潜在写者；完成证明覆盖全部异步访问；设备 owner 与派生文件状态分离；已取得但校验失败的 bytes/guard 仍留存；完成未知者隔离，不阻断就绪 owner 的有界抢救。离线部分的输入闭包、不可变 canonical revision、内容身份、完成收据及 OS 锁也比仅保存 JSON 更接近实际可恢复实现。

## 按严重性的问题

### 中等：deadline 的适用范围尚需在公开 API/transport 合同中钉住

位置：设计 §8.7（第 327、329 行）、§8.13“共同 deadline”（第 510 行）、§10 导出 60s；测试 E05、§8.8 就绪者抢救行。实际落点：`timeline_runtime.py` 第 48–50 行已说明 `read` 的 deadline 只限制 polling，单个 SDK 调用仍依赖 CLI/测试控制器的外层进程 deadline；`read` 取得完成后直接调用 `transport.read_raw`，hook 在一轮就绪者处理中同步留存。

问题不是要求 Python 安全打断卡死驱动，而是设计将“共同 deadline 内有界收尾”写成一般合同，尚未明确等价公开 API 在没有外层控制器时的保证。非阻塞完成 query 不保证后续 D2H、SDK release 或文件 fsync 有界；一个已就绪 owner 进入阻塞调用后，后续就绪者仍可能无法获得抢救机会。现有“query 保持 unknown，B 已完成”的用例不能覆盖这一差异。文档没有承诺任意 ready 均能落盘，这点正确，但仍应避免把 polling deadline 写成所有原生调用的硬时限。

必须在资格冻结前明确：逐 transport 标记哪些操作可轮询/有原生超时、哪些只能由外层控制器限制；区分库 API 的软截止与受控 CLI 的进程截止；外层终止后不发布安全回收或完整保存结论。增加一个明确标注的阻塞 transport 子进程 fixture，验证控制器有界返回、失败阶段准确、既有收据不受损；不在真实设备上制造驱动卡死。若现有执行合同已规定外层控制器，只需在本设计及 API 支持表引用其适用范围，不另建运行框架。

### 低：新增通用结构检查器的能力范围宜做成冻结字段

位置：设计 §0.5“通用 lowering/控制结构”、§8.14“边界证据的最小结构”；测试 §0.2 第一行、P03。

设计正确要求自动生成绑定本次 binary/site/path 的收据，也正确禁止逐算子人工批准。但“已支持的通用结构”目前主要是文字条件。建议接入清单列出检查器/规则版本、支持的结构谓词、拒绝原因代码与匹配到的本次对象范围，便于第三方确认陌生结构确实 fail-closed，避免把人工审计笔记误当运行时自动收据。测试已经规定 ordinary 成功但 profile 失败保留为失败，因此此项不是降低分母的新入口，也不是本轮设计阻断项。

未发现新的高严重性设计缺陷。当前代码中的 `function/stream/num_ctas` 约束、NVIDIA 指纹以及 owner pool 仅有 pending 额度，都是设计 §0.5、§8.13、§10 已明确要修正/补齐的实施差距，不重复列为本轮未识别的架构问题。

## 关键假设及最小验证

| 假设 | 最小验证与失败路径 |
| --- | --- |
| 三后端编译链存在可自动约束的真实区域边界 | 普通有依赖 runtime-K 循环及 load/compute/store，比较 ordinary/稀疏/默认最终对象；核读钟与区域、循环控制及数据依赖。仅 noinline/volatile、正 duration 不够；陌生形态保 raw，修通用检查器，不人工填机器范围授资格。 |
| 物理 logger 与 transport 对布局、发布及全部写者达成同一合同 | 公开入口 grid=1、首末不同、2D/tail；核 pointer 元素单位、最大写址、guard、逐 observer commit。Ascend 独立 cache-line/可见性、GCU 写者与 stride、NV packed 位宽须各自取证；坏 guard 仍保 bytes。 |
| 完成凭据覆盖初始化、kernel、D2H 及 host staging/native/context 的真实访问 | 正常设备顺序正例；CPU 延迟访问 fixture 覆盖初始化/D2H 部分提交异常、release 部分成功。证明完成前不析构/回收，完成且闭包持久化后可回收，不等待 decode 成功。 |
| SDK 能保留已声明支持的并发行为 | 冻结 two-stream/thread/graph 支持表；支持者真实交错提交，核没有逐 launch host wait，不支持者在副作用前拒绝并验证恢复。不得因失败事后改 unsupported。 |
| getter 有可用单位、有效窗口及目标异步所需的比较关系 | 每目标实际 getter/位宽/尺度来源及独立留出验证；epoch/端点误差另证，短位宽排除完整整圈与 reset。未知比例不给 ns；只有尺度不给跨主体比较；当前 reader 回绕限制不改原 tick。 |
| ordinary 对象确有可观测异步机制与物理复用 | 一份真实普通异步样本，至少两代 buffer/flag，核 submit/group/部分 wait/消费、generation 与首轮/steady/drain。静态可能关系、ordinal 或同地址均不替代证据；无法取得则该后端完整 P01/P07 未过。 |
| 输入闭包足以脱离原进程离线消费 | 关闭采集进程，新进程仅用 bundle 与规定证据，经公开 CLI/API 重导；原 source/cache 不可读，禁止设备初始化/应用重放。核实际访问限制及 SHA；缺输入明确失败，不能重建 owner 补救。 |
| 收据/锁/rename/fsync 的文件系统语义符合提交假设 | 在实际部署文件系统记录能力；用同 bundle 的派生写入、收据、索引故障及持锁子进程退出用例，核发现完整结果、无半成品成功索引、合法并发不互相丢失。不能把进程崩溃测试扩大声称已验证断电耐久性。 |

这些验证均有小输入和明确失败出口；三后端时间/异步能力仍是待取证条件。CPU fixture 只验证状态机与拒绝逻辑，不证明 SDK/设备实现遵守假设。

## 验收是否可执行

可以执行，且能发现“接口统一、实际链未通”。测试 §0.2 的真实调用追踪与同一消费链、§8.8 的真实 writer/guard/落盘重读、§8.9 的新进程幂等重导，分别阻断只画接口、只在内存中有字段、只在原 hook 中 retry 的伪通过。P01 在独立大矩阵前要求真实异步和时间资格，能尽早暴露最贵的硬件未知。

独立六数学、cold/warm、实际 SQL/UI 和三名最终代码 reviewer 较重，但文档允许复用真实 bundle 和既有 P/E 样本，并未要求再做第四设备或全排列平台，因此总体工作量与目标匹配。执行时应把每项正例/fixture、已证范围、退出终态及未跑项分别保留；不要把局部 counter-ns 或离线成功提升成源区域/跨主体/异步资格。补足上文 deadline 范围后，剩余验收没有明显无法操作的文字要求。

## 必须修正与非阻断建议

- 必须在资格冻结前补清 SDK 阻塞、公开 API、外层控制器及共同 deadline 的保证边界，并用受控子进程 fixture 验证；不要求安全打断真实驱动调用。
- 非阻断：冻结通用结构检查器的能力谓词与拒绝码；在失败输出直接提示哪些 owner 仍需原进程有界重试、哪些闭包已可新进程重导，避免把尚未落盘的 host bytes 当作离线可恢复产物。
- 非阻断：接入清单直接复用设计 §0.5 的短模板及既有工程索引，不再产生另一套“完成”台账。

上述处置完成只说明设计更可执行；三后端实际时间尺度、边界、资源安全、异步和 Perfetto 仍必须由后续设备与工具证据逐门证明。
