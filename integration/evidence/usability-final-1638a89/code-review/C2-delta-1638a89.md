## C2-01 修复路径

原反例是 compiled census S=8、原 metadata capacity64、实际 grid13，callback 只改变 runtime layout，就让 native 跳过容量设置，分配4128 bytes，而实际 census writer 需要6688 bytes。

新 `Debugger/python/Bindings.cpp:632` 以 `(runtime GCU census || compiled GCU census)` 进入 guard；634–641行同时要求 compiled layout 为 GCU census、runtime layout 与它完全一致。由此两种冲突方向都会在797行 `prepareOwnedLaunch`、任何 buffer 分配之前抛错：

- compiled 是 census，runtime 为空、其他 layout 或缺少可用匹配值。
- runtime 声称 census，compiled 是其他 layout。

合法路径保留642–661行的编译 site 数、site inventory 长度、runtime stride、实际 grid、预算和索引校验，并将 `recordCapacity` 设置为真实 `grid*S`。因此 C64/S8/grid13 的原正控仍应分配104 cells、6688 bytes，不受最初 capacity64 限制。这里没有用运行时 callback 重新定义 compiler S，也没有变成只有 Python 保护。

新 `Debugger/python/flagtree_debugger/api.py:1485` 在1534行调用 binding 之前要求 layout 匹配、编译 S 为1–128的精确 Python int、runtime stride 也是精确 int 且等于编译 S。`None`、空串/其他 layout、bool、float、数字字符串不再通过 callback 路径。原真实 grid 绑定保留；缺少 callback layout/stride 时仍由编译 metadata 填入，正常用户无需新增参数。Ascend 原检查未被替换。
