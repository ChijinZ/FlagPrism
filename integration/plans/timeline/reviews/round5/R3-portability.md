## 已确认设计问题

- **Blocker：无。** 没有发现必须依赖虚构时间、额外完成屏障、逐算子适配或公共厂商分支才能成立的强制路径。

## 设计合理性与实际成本

**新芯片成本的表述可信，但不是低成本保证。** 设计 242、284–294 行明确以 target/toolchain 为单位，分别讨论同工具链新型号、相近模型不同工具链和不同执行模型。编译接入、timer/logger、隐藏参数、发布协议和异步识别仍可能需要重做，不承诺“一个 adapter 即可移植”或第四芯片工期。设计 318、331 行及测试 199、216、220 行要求用真实调用位置、diff 和设备证据描述已发生的成本，这比以接口数量或 LOC 推导未来支持更合理。

**部件组合的边界足够具体。** 设计 294–312 行允许 compiler、transport/decoder、clock、mechanism 独立替换，同时给出 manifest/launch ABI、记录位宽/布局、完成条件、getter/epoch 和机制闭合等兼容轴，以及静态冲突与 raw 才能发现的冲突的不同拒绝阶段。测试 207–215 行要求从实际使用的组合逐轴构造负例；因此不是只靠注册成功授予兼容。无需为了形式统一再建立五套空类。

**公共层与后端职责可实施。** 设计 146–168、216–227、263–270、296 行把优化后的实际 anchors、物理发布/解码、指令语义和状态覆盖留给后端，把身份、引用、完整性、时间算术与展示留给公共层。公共验证器不能独立证明 ISA 规则正确，设计 227 行也明确承认这一边界。设计 314–316 行进一步将 raw 完整性、源导航、区域边界、时间尺度、跨 observer 比较和物理 generation 分开授予资格，避免一个有效证明给整个 bundle 盖章。

**Perfetto 方案与验收可执行。** 设计 92–108、118、333–350 行先约束真实时间语义，再规定标准 protobuf、独立时钟域、track 层次、重叠处理与来源详情。测试 105–130 行固定真实导入器/UI 版本，要求所有正常资格 trace 的 SQL/raw 对照及每后端六份实际 UI 操作，区分“能解析”“内容正确”“可读”。源码导航允许配套 bundle 页面而不假设 Perfetto 原生支持任意本地文件跳转，避免了工具能力承诺过度。SQL 和图形布局需在真实 exporter 上定型，但已有明确的消费语义和失败判定。

**整体实施路线合理，工程量显著。** 第一后端形成小合同，再让三后端检验复用，先 A/B 基础链后 C 完整 P01 再 D 最终验收（设计 318–331 行），可以尽早暴露核心阻碍。默认预算、紧凑选择、pending owner admission、失败留存和重导不重跑的要求相互一致。测试 37–44 行的独立数学矩阵及新增修复回归有较大执行成本，但数量、冻结与失败分母明确，并非无法执行的验收。现有 NVIDIA raw 公开路径只是可复用起点；runtime 3–20、29–44 行及 events 36–41 行准确限制其结论，不应因此否决目标设计，也不能据此判完成。

## 待设备/实现核验的交付风险

以下均不是已确认设计缺陷。每项列出具体张力、最小落实动作与已有验收，不要求设计阶段先交设备结果。

### V1：自动源码区域与最终机器边界之间存在真实编译风险

- **位置：**设计 66–70、146、202、212、314–318 行；runtime 29–44 行；测试 142、159 行。
- **具体张力：**早期源区域可能融合、拆分或消除；LLVM 级依赖和 memory clobber 不自动约束最终机器调度。当前文档明确承认 `llvm_ssa_pending_machine_audit`，所以不能把正 duration 或 PC 对应当作源区域时间证明。
- **最小落实：**无需修改目标；按 site 保存最终 begin/end anchors、所声明被包住的指令/依赖范围和无法证明的理由。自动 planner 若改选更粗区域，保留原意图与实际选择的映射，不能重复同一 fused duration 满足两区域门槛。
- **验收：**复用 P03 与 §8.2 的依赖算术 loop、load/compute/store、原 wait；检查最终对象顺序与 runtime occurrence。缺边界证明的 site 只能保原始 counter 间隔/源导航，不能通过源区域耗时资格。

### V2：时间尺度、epoch 和有效窗口不能由相近芯片或同频率继承

- **位置：**设计 98–108、164、204、309、314–316 行；测试 96、145、210、214–215 行。
- **具体张力：**GCU 的已有比例界限并非精确 1 ns 或共同 epoch；Ascend/NVIDIA 的目标 getter 和跨 actor 比较范围仍需各自证据。已知频率也不能消除截断完整回绕或相邻短事件的不确定性。
- **最小落实：**无需放宽门槛；clock proof 冻结实际 getter、记录位宽、比例/舍入、有效窗口、共享误差项及适用 device/epoch。clock provider 与 decoder 的 tick 格式兼容必须实际检查。
- **验收：**P01 的真实 getter/尺度与所需跨主体比较证据；P06/E09 的错域、错目标、整圈歧义、大 tick 和端点不确定负例。独立域可以单独导出，但不能据此给异步时间箭头通过票。

### V3：逻辑 group 关联不足以满足最终物理复用资格

- **位置：**设计 112、166–168、205、274、310、314 行；测试 64–71、146、195–196、211 行。
- **具体张力：**通用模型允许只有逻辑 group 的有效部分结果，但最终 P07 必须有每后端两轮真实 buffer/flag 复用及代际证据。当前 NVIDIA 已有逻辑组模型不等于这项资格；不同后端也不能硬套相同 producer/consumer 粒度。
- **最小落实：**按普通编译对象选择真实可观测机制，列全状态变更、wait 覆盖集合与物理 slot/flag 代际来源。若当前候选没有可证明的物理复用，另登记合法样本或保持门未通过，不能用 ordinal 补造 generation。
- **验收：**P07 两轮实际复用、首轮/steady state/drain；部分 wait、多消费者、丢 commit 和 opaque 状态变更负例。后端给出机制事实，公共消费者核集合与完整性；ISA/SDK 规则另以真实产物核对。

### V4：异构发布/回收与并发 admission 是独立于解码正确性的风险

- **位置：**设计 86–88、223、236–240、265、307–308、312 行；runtime 68–83 行；测试 160–161、174–181、193–194、213 行。
- **具体张力：**Ascend cache-line 可见性、GCU 实际写者、NVIDIA timer/storage ABI 及 stream 完成条件不能被共同 schema 掩盖。初始化也可能提交设备写入；timeout/host 返回不证明可回收。只测单调用预算不能证明 pending 总量安全。
- **最小落实：**无需统一物理 ABI；每后端明确初始化、提交、完成、D2H 和隔离资源的状态转移，以及所声明并发范围。部件冲突在其可识别阶段拒绝，不能伪称所有错误都可启动前发现。
- **验收：**P05 的真实发布/完整 payload；E03/E05 与 §8.3 的 pending 超限、交错 owner、异常阶段、超时不早回收及安全恢复。CPU transport fixture 只补状态机，不能替代声明支持的真实并发。

### V5：标准 Perfetto 的实际布局和 flow 导入仍需端到端原型确认

- **位置：**设计 206、337–350 行；测试 105–130、147、212 行。
- **具体张力：**正确 canonical 数据不保证 TrackEvent 的重叠、track 层次、flow 端点和来源 args 在指定版本的 Trace Processor/UI 中仍完整且易读。把多个 in-flight operation 塞到错误 B/E stack，或隐藏误差/缺失字段，都会破坏解释。
- **最小落实：**首条真实纵向链就冻结一个小的 canonical→track/slice/instant/flow 映射及 executed SQL，不等三后端全部完成才发现导入问题；不需要更换标准 UI 或增加厂商 exporter。
- **验收：**P01 的真实导入，P08/§7 全资格 trace 的事件/raw/flow 集合逐条核对，§8 三后端实际 overview、zoom、slice 和 flow 点击；保持原 bundle SHA，检查完整 importer stats。

## 可选建议（不影响本轮通过）

1. **接入清单增加“复用条件”和“失效条件”并列栏目。** 位置：设计 288–312、331 行；测试 207、213、216 行。现有要求已经覆盖这些内容，但集中到同一清单会更便于下一型号判断哪些部件可复用、哪些证明必须重做。最小修订仅是清单展示；验收用一个合法组合和一个单轴冲突定位所需证据，不新增设备或资格矩阵。
2. **把小合同冻结项与现有 P/E 编号做一页交叉索引。** 位置：设计 198–210 行；测试 138–149、189–216 行。设计已具备所需约束，分布较广容易使实施人员遗漏。最小修订是索引而非新状态日志；验收可从任一兼容轴或资格结论找到生产点、validator 和既有测试，不要求新增抽象。

因此可进入按 A/B/C/D 分段实施与核验；不能直接授予最终可交付结论。若真实设备证明任一必需机制不可取得，应依合同保留最小技术阻碍并报告，不能把该条件通过改为无条件完成。
